# ФОРМА — визуализация кухонь

Фронтенд MVP веб-приложения для мебельщиков. Мастер приезжает на замер, фотографирует
существующую кухню прямо в браузере телефона, выбирает материалы, цвет, палитру, стиль,
столешницу, освещение и размеры — и получает визуализацию будущей кухни, которую можно
сразу показать клиенту.

Приложение работает **полностью автономно**: без запущенного бэкенда весь сценарий
проходится от начала до конца на встроенных демо-данных.

---

## 1. Требования

- **Node.js** 20.19+ или 22.12+ (проверено на 24.x)
- **npm** 10+
- Современный браузер: Chrome, Safari, Firefox, Edge
- Для съёмки через камеру нужен защищённый контекст: `https://` или `localhost`

## 2. Установка

```bash
npm install
```

## 3. Запуск

```bash
npm run dev
```

Приложение откроется на `http://localhost:5173`. Дев-сервер слушает все интерфейсы
(`host: true`), поэтому его можно открыть с телефона в той же сети по адресу
`http://<ip-компьютера>:5173` — так удобнее всего проверять основной сценарий.

> Камера в браузере доступна только на `https://` или `localhost`. При открытии по
> локальному IP приложение автоматически переключается на системный выбор фотографии
> (`<input capture="environment">`) — сценарий не ломается.

Другие команды:

| Команда | Что делает |
| --- | --- |
| `npm run build` | Проверка типов + production-сборка в `dist/` |
| `npm run preview` | Локальный просмотр собранного приложения |
| `npm run typecheck` | Только проверка типов TypeScript |
| `npm run lint` | Статический анализ (oxlint) |
| `npm run icons` | Перегенерация иконок PWA в `public/icons` |
| `npm run samples` | Перерисовка демонстрационных изображений в `public/samples` |

### Открыть на телефоне

```bash
npm run dev:mobile
```

Скрипт печатает адрес в локальной сети и QR-код к нему — наведите камеру телефона и
откройте ссылку. Телефон и компьютер должны быть в одной сети Wi-Fi.

Сервер поднимается по HTTPS с самоподписанным сертификатом: браузер один раз покажет
предупреждение, нужно нажать «Дополнительно» → «Перейти на сайт». Без HTTPS браузер не
даст доступ к камере, и приложение переключится на выбор фотографии из галереи.

Команда `npm run dev:lan` делает то же самое, но по HTTP — быстрее, но без съёмки через
камеру. Переменная окружения задаётся синтаксисом macOS и Linux; в Windows используйте
`set HTTPS=1 && vite --host`.

В открытом приложении можно нажать «Поделиться» → «На экран «Домой»» (Safari) или
меню → «Установить приложение» (Chrome): оно добавится на домашний экран и будет
открываться во весь экран, без адресной строки.

### Развёртывание

`npm run build` кладёт статику в `dist/`. Приложение использует клиентскую маршрутизацию,
поэтому на хостинге нужен SPA-fallback: любой неизвестный путь должен отдавать
`index.html` (в nginx — `try_files $uri /index.html;`, в Netlify/Vercel — правило rewrite
`/* → /index.html`). Иначе прямые ссылки вида `/projects` вернут 404.

Установка на домашний экран и работа без сети требуют HTTPS — сервис-воркер
регистрируется только в собранном приложении и только в защищённом контексте.

## 5. Демо-режим и офлайн-рендер

При `VITE_USE_MOCK_API=true` (значение по умолчанию) приложение использует встроенный
демо-бэкенд `src/api/mockBackend.ts`. Он повторяет контракт реального API и добавляет
реалистичные задержки.

Что входит в демо-данные:

- 6 материалов фасадов, 12 цветов, 6 фактур;
- 5 материалов и 6 цветов столешниц;
- 8 палитр, 7 стилей, 6 схем освещения, 7 дополнительных параметров;
- 3 демонстрационных проекта в разделе «Мои проекты».

### Как получается изображение без бэкенда

Визуализацию считает собственный движок в `src/render` — трассировщик лучей, который
строит трёхмерную сцену кухни по выбранным параметрам. Но главное не он, а то, **куда**
эта кухня попадает.

#### Комната остаётся настоящей фотографией

Приложение не перерисовывает помещение. Оно разбирает снимок (`src/analysis`), находит
геометрию и свет, вписывает построенную кухню в кадр и оставляет всё остальное нетронутым:

1. **Разбор снимка** — градиенты и проекции дают стык пола со стеной, линию столешницы,
   стык потолка, границы окон, направление и тон света, цвета стен, пола и потолка.
2. **Расчёт камеры** — по линии пола, линии столешницы и введённым размерам помещения
   решаются наклон камеры, высота съёмки и расстояние до стены. Угол обзора и высота
   берутся как априорные: по одному кадру они не восстанавливаются однозначно.
3. **Рендер только кухни** — стены, пол, потолок и окно помечены как невидимые. Они
   продолжают освещать сцену, отражаться и принимать тень, но в кадр не попадают.
4. **Тень на реальный пол** — лучи, прошедшие мимо мебели, попадают в плоскость пола и
   считают, какую долю света перекрыла кухня. Так на настоящем полу появляется тень.
5. **Совмещение** — экспозиция рендера подгоняется под яркость снимка, просветы между
   модулями закрываются цветом стены, кадр складывается с фотографией.

Следствия такого подхода: перспектива, стены, потолок, пол, окна и двери не могут
исказиться, лишние объекты не появляются, а материалы и цвета ровно те, что выбраны в
каталоге. Характерных ошибок генеративных моделей — плавающих шкафов, вытяжки сквозь
шкаф, второго окна, невозможных теней — здесь не бывает по построению.

Окно с фотографии переносится в сцену: фартук и верхние шкафы разрезаются по проёму,
а свет приходит с той же стороны, что и на снимке.

#### Что считается в самой кухне

- геометрия собирается из размеров помещения, высоты и глубины столешницы;
- материалы процедурные — волокно дерева, прожилки камня, зерно кварца, швы между
  дверцами, ручки, плитка фартука, половая доска;
- освещение — площадные источники: окно, потолочный свет, отражение от пола, подсветка
  рабочей зоны, подвесы над островом;
- мягкие тени, затенение в углах, отражения на камне, глянце и полу;
- кадр «проявляется» как фотография: свечение бликов, тональная компрессия, зерно;
- шум трассировки снимает демодулированный à-trous-фильтр, поэтому текстуры не мылятся.

Расчёт идёт в Web Worker, три варианта параллельно. На четырёхъядерной машине —
около шести секунд.

#### Уровни качества

В разделе «Профиль» выбирается один из трёх режимов; по умолчанию — «Сбалансированно».

| Режим | Разрешение | Когда |
| --- | --- | --- |
| Быстро | 640 px | Быстро перебрать варианты |
| Сбалансированно | 800 px | Показ клиенту |
| Качество | 1040 px | Максимальная детализация |

Разрешение дополнительно ограничивается по числу ядер устройства.

#### Проверка результата и повторы

Каждый кадр проверяется на пустоту, черноту, пересвет и бессмысленную долю покрытия.
При провале выполняется **одна** повторная попытка — с другим зерном и без вписывания
в фотографию. Бесконечных повторов нет. Ход генерации, зерно, разрешение, параметры
камеры и доля покрытия пишутся в консоль браузера.

Зерно расчёта хранится вместе с генерацией. «Создать ещё» меняет **только** зерно:
материалы, цвет, стиль и свет остаются прежними, поэтому все варианты согласованы.

#### Проверочные прогоны

```bash
npm run test:analysis     # разбор снимка против известной геометрии
npm run test:composite    # вписывание новой кухни в снимок старой
npm run test:regression   # десять типовых сценариев из ТЗ
npm run test:drawings     # чертежи и спецификация
```

Регрессия печатает по каждому сценарию параметры камеры, покрытие, яркость и доверие,
а кадры складывает в `regression/`.

#### Крупный кадр по запросу

Три варианта считаются в рабочем разрешении, чтобы не заставлять ждать на замере.
Кнопка «Скачать крупно» на карточке результата пересчитывает выбранный вариант в
1600 px тем же зерном — картинка получается той же, только детальнее. Расчёт занимает
до минуты, и приложение честно об этом предупреждает.

#### Когда вписывание не выполняется

Модель кухни фронтальная: прямая линия у стены, камера примерно на уровне глаз, стена
целиком в кадре. Перед расчётом снимок проверяется на пригодность
(`analysis.suitability`): виден ли стык пола со стеной, есть ли сплошная линия
столешницы поперёк кадра, не снят ли кадр под углом (наклон кромки больше 3,5°), смотрит
ли камера на стену с кухней.

Если проверка не прошла — **вписывание не запускается**. Приложение считает отдельную
визуализацию с выбранными материалами и прямо пишет на экране результата, что кухню не
вписали и почему, с подсказкой, как переснять. Плохо совмещённый кадр выглядит хуже, чем
честный отдельный рендер, поэтому такой отказ — часть нормальной работы.

Что не поддерживается вписыванием:

- угловые и П-образные кухни — модель описывает прямой фронт;
- съёмка сверху или сбоку под заметным углом;
- кадр, где кухня занимает часть стены и уходит за край.

#### Ограничения расчёта

- Угол обзора и высота съёмки по одному кадру неоднозначны, поэтому берутся типовыми;
  при нестандартной съёмке масштаб кухни может немного не совпасть.
- Если новая кухня меньше прежней, по краям могут остаться её фрагменты: широкие
  просветы автоматически не закрашиваются, чтобы не стереть настоящую обстановку.
- Вытяжка рисуется только по отдельной галочке «Добавить вытяжку» и по умолчанию
  выключена: на большинстве замеров вытяжка уже стоит.

## 6. Чертежи для производства

Раздел «Чертежи» строит рабочие листы из **той же сцены**, что и визуализация, поэтому
размеры на картинке и в цехе не разойдутся. Ничего не генерируется — геометрия
вычисляется:

- **Развёртка по стене** — фронтальный вид с разбивкой на модули, размерными цепочками,
  высотами столешницы, фартука и верхнего яруса, оконным проёмом и техникой;
- **План** — вид сверху с глубиной модулей, пеналом, островом и шириной прохода;
- **Спецификация** — таблица модулей: ширина × высота, глубина, число дверец, фасад.

Фронт разбивается на модули стандартной ширины (`splitRun` в `src/drawings/layout.ts`):
берётся ближайшее целое число корпусов, ширина выравнивается по 10 мм, остаток уходит в
последний модуль. Оба чертежа скачиваются в SVG — он открывается в любом векторном
редакторе и печатается без потери качества.

Размеры помещения задаёт замерщик, включая **глубину** — без неё план был бы
приблизительным.

## 7. Разбор фотографии через Claude

Отдельно от генерации изображений подключается Claude — он смотрит на снимок и
возвращает структурированный разбор:

- что видно на фотографии;
- что помешает монтажу: выступы, трубы, узкие проходы, положение окон и розеток;
- 2–4 рекомендации по интерьеру;
- **готовый набор параметров** из каталога — материал, цвет, фактура, столешница,
  палитра, стиль и свет, с обоснованием.

Кнопка «Подобрать параметры по фотографии» появляется на экране настройки, когда ключ
задан в «Профиле». Ответ приходит строго по схеме (`output_config.format` + Zod), поэтому
идентификаторы всегда существуют в каталоге и применяются одним нажатием.

**Claude не рисует изображения.** Это текстово-визуальная модель: она разбирает снимок и
возвращает данные. За картинку отвечает офлайн-движок или сервис генерации из раздела 8.

Модуль подключается динамически, поэтому SDK не попадает в основной бандл и не грузится
у тех, кто разбором не пользуется.

## 8. Подключение генерации изображений (ИИ)

Приложение умеет брать визуализации из трёх источников. Переключение — в разделе
«Профиль» → «Как создаются визуализации».

| Источник | Когда используется | Что нужно |
| --- | --- | --- |
| Офлайн-рендер | По умолчанию | Ничего, работает без сети |
| Сервис генерации | Выбран в профиле | Ключ доступа пользователя |
| Рабочий сервер | `VITE_USE_MOCK_API=false` | Свой бэкенд (раздел 7) |

### Сервис генерации

Поддерживаются два варианта:

- **OpenAI** — запрос `POST https://api.openai.com/v1/images/edits` с исходной
  фотографией и описанием сцены. Модель по умолчанию `gpt-image-1`.
- **Свой сервис** — любой адрес, который принимает
  `{ prompt, image, variants }` и возвращает `{ images: ["data:image/png;base64,…"] }`.
  Это самый быстрый способ подключить собственный ComfyUI или FastAPI без правок кода.

Описание сцены собирается в `src/api/ai/prompt.ts` из выбранных материалов, цветов,
палитры, стиля, освещения, размеров и дополнительных параметров. Пользователю текст
запроса не показывается никогда.

### Важно про ключ

Ключ сохраняется только в `localStorage` браузера пользователя и не попадает ни в
репозиторий, ни в сборку. Тем не менее запрос уходит из браузера, а значит ключ виден в
инструментах разработчика. Это допустимо для демонстрации и работы «со своим ключом», но
**в рабочем продукте ключ должен храниться на сервере**, а приложение — обращаться к
своему бэкенду. Именно поэтому режим по умолчанию — офлайн-рендер, а prompt в рабочей
схеме собирает бэкенд.

## 9. Подключение FastAPI

1. Укажите адрес бэкенда и выключите демо-режим:

   ```dotenv
   VITE_API_URL=https://api.example.com/api/v1
   VITE_USE_MOCK_API=false
   ```

2. Перезапустите дев-сервер (переменные читаются при старте Vite).

Ожидаемые эндпоинты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/catalog/materials` | Материалы фасадов |
| `GET` | `/catalog/colors` | Цвета фасадов |
| `GET` | `/catalog/textures` | Фактуры |
| `GET` | `/catalog/palettes` | Палитры |
| `GET` | `/catalog/styles` | Стили |
| `GET` | `/catalog/countertops` | Столешницы: `{ materials, colors }` |
| `GET` | `/catalog/lighting` | Схемы освещения |
| `GET` | `/catalog/options` | Дополнительные параметры |
| `POST` | `/projects` | Создание проекта |
| `POST` | `/projects/{projectId}/photo` | Загрузка фотографии, `multipart/form-data`, поле `photo` |
| `GET` | `/projects` | Список проектов |
| `GET` | `/projects/{id}` | Проект |
| `PATCH` | `/projects/{id}` | Обновление проекта |
| `DELETE` | `/projects/{id}` | Удаление проекта |
| `POST` | `/projects/{projectId}/generations` | Запуск генерации |
| `GET` | `/generations/{id}` | Статус генерации |
| `GET` | `/generations/{id}/events` | Поток событий (SSE) |

Тело запроса на генерацию — только структурированные параметры:

```json
{
  "material_id": "enamel",
  "color_id": "graphite",
  "palette_id": "graphite-oak",
  "texture_id": "matte",
  "style_id": "premium-modern",
  "countertop_id": "quartz",
  "countertop_color_id": "top-light-stone",
  "lighting_id": "warm",
  "dimensions": {
    "roomWidth": 4200,
    "roomHeight": 2700,
    "counterHeight": 900,
    "counterDepth": 600
  },
  "options": {
    "keep-layout": true,
    "keep-windows": true,
    "keep-doors": true,
    "keep-perspective": true,
    "built-in-appliances": true,
    "accent-lighting": false,
    "island": false
  }
}
```

**Prompt Builder живёт на бэкенде.** Фронтенд не формирует и не показывает текст запроса
к ИИ — он отправляет только идентификаторы выбранных параметров.

События прогресса (SSE, одно JSON-сообщение на событие):

```json
{
  "generationId": "gen_123",
  "status": "processing",
  "stage": "interior",
  "progress": 60,
  "results": []
}
```

`status` — `queued | processing | completed | failed`, `stage` — `analyze | materials |
interior | render`. Если бэкенд не сообщает прогресс, передавайте `"progress": null` —
интерфейс покажет бесконечный индикатор вместо шкалы. Если поток событий недоступен,
фронтенд автоматически переходит на опрос `GET /generations/{id}`.


## 11. Архитектура

**Слои.** UI-компоненты не обращаются к сети напрямую. Любой запрос проходит через
`src/api/*`, который сам решает, обратиться к демо-бэкенду или к реальному серверу.
Замена mock на продакшен не затрагивает ни один компонент.

**Состояние.** Используется React Context без внешних менеджеров состояния:

- `ToastProvider` — уведомления и человекочитаемые ошибки;
- `CatalogProvider` — справочники, загружаются один раз;
- `ProjectProvider` — текущий проект: фотография, параметры, статус генерации, результаты.

**Источник визуализаций.** `getGenerationSource()` в `src/api/generations.ts` — единственное
место, где решается, откуда придёт картинка: рабочий сервер, подключённый сервис генерации
или офлайн-движок. UI об этом не знает.

**Реальное время.** Ход генерации приходит через интерфейс `GenerationSubscription`.
Транспорт скрыт: офлайн-движок отдаёт настоящий прогресс расчёта, сервис генерации —
смену этапов с бесконечным индикатором (прогресса он не сообщает), продакшен — через
Server-Sent Events с автоматическим откатом на опрос статуса. Перейти на WebSocket можно,
изменив только `subscribeToGeneration`.

**Фотографии.** `src/lib/image.ts` проверяет тип и размер файла (до 15 МБ), учитывает
EXIF-поворот снимков с телефона, уменьшает изображение до 1920 px по длинной стороне и
сжимает его до разумного веса перед отправкой.

**Типизация.** Строгий режим TypeScript, все ответы API описаны интерфейсами, `any` не
используется.

**Доступность.** Выбор параметров построен на настоящих `radio` и `checkbox`, поэтому
работает клавиатура и скринридер. У всех кнопок-иконок есть текстовые подписи, целевые
области нажатия не меньше 44 px, фокус виден.

## 12. Как добавить новый материал

1. Откройте `src/mock/materials.ts`.
2. Добавьте элемент в массив `MOCK_MATERIALS`:

   ```ts
   {
     id: 'lacquer',
     name: 'Лак',
     caption: 'Полуматовый',
     description: 'Многослойное лаковое покрытие с мягким отражением.',
     preview: { base: '#DCD6CC', highlight: '#F2EFE9', shade: '#B5AEA2', grain: 'gloss' },
   }
   ```

3. `grain` выбирается из `flat | wood | veneer | stone | marble | linear | gloss | speck` —
   от него зависит и карточка выбора, и демонстрационная визуализация.

Материалы столешниц добавляются так же в `src/mock/countertops.ts`, цвета — в
`src/mock/colors.ts`.

## 13. Как добавить новую палитру

1. Откройте `src/mock/palettes.ts`.
2. Добавьте элемент в `MOCK_PALETTES` — от 3 до 5 образцов:

   ```ts
   {
     id: 'green-oak',
     name: 'Зелень и дуб',
     description: 'Спокойная зелёная база с тёплым древесным акцентом.',
     swatches: [
       { name: 'Оливковый', hex: '#6E7359' },
       { name: 'Молочный', hex: '#EAE2D5' },
       { name: 'Дуб', hex: '#C09A6B' },
     ],
   }
   ```

Первый образец палитры считается основным: если цвет фасадов ещё не выбран, приложение
подставит ближайший к нему цвет из каталога.

## 14. Как заменить mock API на production API

1. Установите `VITE_USE_MOCK_API=false` и укажите `VITE_API_URL`.
2. Убедитесь, что бэкенд отвечает на эндпоинты из раздела 9 и разрешает CORS для домена
   фронтенда.
3. Приведите ответы к типам из `src/types` — это единственный контракт между слоями.
4. При необходимости замените транспорт прогресса в `src/api/generations.ts`
   (SSE → WebSocket); интерфейс подписки менять не нужно.
5. Удалять `src/mock` и `src/render` не требуется: офлайн-режим остаётся рабочим
   запасным вариантом для демонстраций и мест без связи.

Главный экран → камера → предпросмотр снимка → подтверждение → настройка проекта →
генерация → результаты → полноэкранный просмотр → повторная генерация с изменёнными
параметрами → сохранение в «Мои проекты».
